# HomeMind Pi4 Core 0.5.2 변경 요약

## 핵심 안정성 보완

- ACK가 없을 때 3초 간격으로 같은 `command_id`를 최대 세 번 전송한다.
- 세 번째 시도에도 ACK가 없으면 Task를 `failed`로 끝내고 `ACK_TIMEOUT`을 UI에 전달한다.
- ACK 재시도와 최종 실패 판정은 벽시계가 아니라 부팅 후 경과시간을 사용한다.
- 재부팅 뒤 Pi4 시간이 과거로 돌아가거나, DB의 명령 시각이 미래값이어도 명령이 무한 대기하지 않는다.
- 최신 heartbeat·시스템 상태·작업 목록은 벽시계가 아니라 SQLite 입력 순서를 우선해 재부팅 전의 큰 날짜가 새 상태를 가리지 않는다.
- Pi4의 현재 시간이 신뢰 가능한지와 부팅 후 경과시간을 snapshot의 `clock`에 포함한다.
- 시간이 신뢰되지 않아도 센서 원본은 삭제하지 않고 부팅 ID와 부팅 후 수신 시간을 함께 저장한다.
- 장치 오프라인 15초 판정과 저장공간 정기검사도 부팅 후 경과시간을 사용한다.
- 저장공간은 70%에서 경고만 발생하며 자동 삭제는 계속 비활성화되어 있다.

## Flutter UI 보완

- 최근 SQLite 작업 최대 100개를 `기록` 화면에 표시한다.
- Task 실패 원인과 재시도 가능 여부를 표시한다.
- Pi4 시간이 신뢰되지 않으면 작업·시스템 날짜를 `시간 미확인`으로 표시한다.
- 기존 MQTT 자동 재연결, 장치 오프라인, 센서·시스템 상태 화면을 유지한다.

## 검증과 배포

- ARM64 격리 selftest 27개 및 DB 무결성 검사를 통과했다.
- 미래 벽시계 값을 강제로 넣은 시험에서도 attempt 1·2·3 뒤 `ACK_TIMEOUT`으로 끝나는 것을 확인했다.
- 2시간 고속 센서 시험 3회(총 6시간)와 실제 재부팅 자동복구를 통과했다.
- 기존 운영 DB와 설정을 보존하는 업그레이드 구조다.
- Atlas 재부팅 때 Core가 실제 자동 시작되도록 읽기 전용 루트를 잠시 안전하게
  전환해 `/etc/systemd/system`의 서비스 파일을 갱신하고 즉시 읽기 전용으로 복구한다.
- 다른 UI가 상태를 조회 중이어도 자체검사는 자신의 `request_id` 응답만 판정한다.
- `FAN-01`은 화장실 환기 팬이며 공식 zone과 Flutter 표시는 `bathroom`/`화장실`이다.
