# HomeMind 노트북 + Pi4 11시간 작업 최종 보고서

작성일: 2026-09-04  
최종 설치 Core: `pi4-core-0.5.2`

## 1. 작업 목표

노트북 Flutter UI와 Pi4 MQTT·C++·SQLite 백엔드가 실제로 왕복 통신하고,
ESP32가 없어도 가상 장치로 세 시나리오와 예외 상황을 반복 검증한다. 운영 DB와
설정은 보존하고 자동 삭제·자동 백업은 사용하지 않으며, 저장공간 경고 시험을 위해
디스크를 실제로 채우지 않는다.

## 2. 구현 결과

- Flutter에서 귀가 준비, 취침 준비, 야간 침대 이탈 시나리오 요청
- Pi4가 시나리오 명령을 발행하고 가상 ESP32 ACK를 받아 완료 처리
- ACK가 없으면 같은 command ID로 3초 간격 attempt 1·2·3 재전송
- 세 번째 시도 후에도 ACK가 없으면 `ACK_TIMEOUT` 실패 및 UI 안내
- 센서값 범위·자료형·등록 출처 검사와 잘못된 원본 보존
- heartbeat 중단 15초 뒤 장치 offline 처리
- MQTT 중단 뒤 Flutter 자동 재연결 및 SQLite snapshot 복구
- SQLite 최근 작업 100개, 센서·장치·시스템·오류·용량 상태 UI
- Pi4 시계가 신뢰되지 않을 때 `시간 미확인` 표시와 부팅 ID·uptime 저장
- 장치 오프라인, 저장공간 점검, ACK 기한을 부팅 후 경과시간 기준으로 처리
- DB 저장공간 70% 경고만 사용하고 자동 삭제는 비활성화
- 더블클릭 Pi4 상태 점검 도구에 서비스·Core 해시·버전·DB·용량·시계 표시
- AArch64 재설치 패키지와 기존 설정 보호 목록 생성
- 화장실 환기 팬 `FAN-01`의 공식 위치·UI·문서를 `bathroom`으로 통일
- Atlas 읽기 전용 루트에서도 Core 자동 시작 파일을 안전하게 설치하도록 IPK 보완
- 여러 UI가 동시에 상태를 조회해도 자체검사가 자기 `request_id` 응답만 판정하도록 보완

## 4. 데이터 안전 확인

- 운영 DB: `/data/share/homemind/db/homemind.db`
- `PRAGMA integrity_check`: 작업 중 반복 확인 결과 `ok`
- `automatic_delete_enabled=false`
- 자동 백업: 사용하지 않음
- 자동 삭제: 사용하지 않음
- 실제 디스크 채우기: 하지 않음
- 장시간 센서 데이터: 운영 DB가 아닌 별도 시험 DB에 저장
- 이전 운영 Core: Pi4의 `/data/share/homemind/rollback-11h-20260903`에 보존
- 최종 확인 시 운영 DB: 82.27MiB, 이벤트 36,562건, commands 64건,
  ACK 91건, telemetry 5,470건, heartbeat 22,791건, 무결성 `ok`

## 6. 작업 후 남는 실물 연동

다음 항목은 실제 Pi5·ESP32·센서·액추에이터가 준비되어야 완료할 수 있다.

- Pi5 Atlas ARM64 앱 빌드·설치와 1024×600 전체 화면·터치 확인
- 실제 ESP32 펌웨어에 공식 장치 ID, MQTT 인증, ACK 중복 처리 적용
- 실제 카메라 인형 인식 모델, 조명 조건, 가림, 임계값 조정
- 실제 LED·FND·팬·서보의 전원 분리, 레벨 컨버터, 배선 및 부하 시험
- 실제 사용자 동선으로 귀가 → 취침 → 야간 이탈 시연

## 7. 최종 판정

노트북과 Pi4만으로 수행 가능한 범위는 **통과**다. 실제 MQTT 양방향 통신,
가상 장치 ACK, 센서 검증, 15초 오프라인, 시간 오류 보호, 저장공간 70% 경고,
SQLite 보존, 총 6시간의 2시간 안정성 시험 3회, 실제 재부팅 자동복구와 최종
회귀시험을 확인했다. 자동 삭제와 자동 백업은 끝까지 사용하지 않았고 디스크를
시험 목적으로 채우지 않았다. 이후 남은 일은 6절의 실제 Pi5·ESP32·센서·구동부
연동이다.
