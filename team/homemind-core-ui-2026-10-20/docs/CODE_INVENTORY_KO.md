# HomeMind 코드 포함 범위

기준일: 2026-10-20

## 결론

`HomeMind_Full_Handoff_2026-10-20.zip`에는 **현재 이 작업 폴더에서 실제로 작성한 코드가
전부 포함**되어 있다. 다만 아직 담당자가 구현하지 않은 ESP32 실장비 펌웨어와 Pi5 비전
인식 코드는 존재하지 않으므로, 프로젝트의 최종 완성 코드 전체라는 뜻은 아니다.

## 현재 작성된 코드 규모

- 소스·설정 파일: 119개
- 코드·설정 합계: 약 14,461줄
- 전체 ZIP 항목: 약 192개
- Pi4 C++: 8개 `.cpp`, 약 4,111줄
- Flutter/Dart: 23개 `.dart`, 약 5,374줄
- C/C++ 헤더: 14개, 약 1,382줄
- MQTT/JSON 계약: 31개 JSON, 약 1,107줄
- 설치·시험·DB 스크립트: PowerShell, Python, Shell, SQL 포함

ZIP 용량이 약 7.8MB인 이유는 소스 코드와 JSON이 매우 잘 압축되고, 200MB 이상을 차지하던
Flutter 빌드 캐시와 CMake 임시 산출물을 제외했기 때문이다. 캐시는 코드가 아니며 다시 생성된다.

## 포함된 구현

- Pi4 C++ MQTT/TaskFlow 백엔드
- SQLite 스키마와 마이그레이션·검증 코드
- command 재시도, ACK, 중복 방지, offline 판정
- 센서값 규칙과 공식 장치 ID 검증
- 세 HomeMind 시나리오
- P0 안전, 개인정보, 피드백, 저장공간·시간 보호
- Flutter UI 전체 소스
- Flutter MQTT 실제 연결 코드와 Mock 모드
- UI 자동 테스트와 Pi4 통합시험 도구
- MQTT JSON Schema와 예제
- systemd, Mosquitto, Atlas IPK 패키징 소스
- 빌드된 ARM64 실행 파일과 IPK
- ESP32 구현에 필요한 상세 인수인계 문서

## 아직 작성되지 않은 코드

다음은 누락된 것이 아니라 앞으로 해당 담당자가 구현해야 하는 부분이다.

1. ESP32·ESP8266의 실제 Arduino/PlatformIO 펌웨어
   - GPIO 핀은 실물 배선 전이라 확정되지 않음
   - 현재는 Pi4의 가짜 ESP32 simulator로 통신 규격만 검증함
2. Octopus 실제 XY 모터 펌웨어
3. Pi5 V4L2 카메라 사람·인형 인식 코드
4. 학습 데이터셋과 학습된 비전 모델
5. 실제 센서 드라이버와 보정 코드
6. Pi5 실물 Atlas/Wayland 최종 빌드 결과

## 운영 장비에만 있는 데이터

- 현재 Pi4 SQLite 운영 DB
- Pi4의 실제 `mosquitto.passwd`
- Pi4에 배포된 `/data/share/homemind/config/` 런타임 설정

이 데이터는 노트북 프로젝트가 아니라 물리 Pi4 내부에 있다. 팀이 같은 Pi4를 이어받으면 그대로
사용할 수 있다. 별도 백업 ZIP이 필요하면 Pi4 연결 후 운영 스냅샷을 추가로 만들어야 한다.

## 담당자가 이어서 만들 코드

- ESP32 담당자: `docs/ESP32_HANDOFF_KO.md` 규격대로 펌웨어 작성
- Pi5/비전 담당자: perception JSON을 발행하는 카메라 인식 프로그램 작성
- 통합 담당자: 실제 센서·액추에이터를 연결해 세 시나리오와 오류 시험 수행

따라서 팀원에게는 “현재 작성한 코드는 전부지만, ESP32와 비전 실장비 코드는 다음 단계”라고
설명하면 된다.

## 다른 위치에 추가 코드가 있을 가능성

Pi4에는 주로 컴파일된 실행 파일, 설정, SQLite DB가 있으며 원본 C++ 프로젝트 전체가 배포되는
구조가 아니다. 따라서 ZIP이 작아 보이는 이유를 “나머지 소스가 Pi4에 있기 때문”이라고 해석하면
안 된다.

다만 다른 팀원이 다음 위치에 별도로 코드를 작성했을 가능성은 있다.

- 팀원 개인 PC
- 별도 GitHub/Git 저장소나 브랜치
- Google Drive
- 메신저로 전달된 `.ino`, PlatformIO, Flutter 또는 Python 파일

이 경우 해당 코드는 이 작업 폴더의 관리 범위 밖이므로 팀원에게 직접 받아 통합해야 한다. 특히
ESP32 펌웨어나 Pi5 비전 코드가 이미 있다고 주장하는 팀원이 있다면 파일만 받지 말고 원본 저장소,
사용 보드, 라이브러리 버전, 핀맵, 실행 방법도 함께 받아야 한다.

물리 Pi4가 다시 연결되면 배포 바이너리·설정·운영 DB를 백업하고 로컬 ZIP과 해시를 비교한다.
배포 바이너리가 다르다면 바이너리를 역으로 소스라고 취급하지 말고, 그 바이너리를 빌드한 별도
소스 저장소가 있는지 먼저 확인한다.
